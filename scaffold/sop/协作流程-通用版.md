# 协作流程（Scaffold 通用版，v0.4 骨架）

> 项目特定参数一律引用 pj-config.md；本文件只含跨项目公共流程。

## 1. 执行形态
Claude Code 单 session 架构师常驻 + dev/QA subagents 瞬态拉起（可并行）+ G 日终审核。

## 2. 自动化主线
白天全自动（spawn → 执行 → commit 本地 → 裁决回填 → 循环）→ 日终 G 逐条审核 → 统一 push。

## 3. 角色边界
- 架构师：唯一写开发状态.md；派发只给「目标+设计输入+DoD+硬约束」；裁决须实证证据；不改代码
- Dev：实现 + 门禁全绿 + 交接文档（提交信息公示定稿）；对架构师可质疑（≤2 轮）
- QA：评审（finding schema + 证据链 + 定级）；验证方式自选（只读或独立 worktree）
- G：日终审核（7 项清单）；不介入白天流程；拍板兜底

## 4. 特殊流程强制复盘
故障/方案矫正 → 三层根因（技术-流程-组织，分开管理根因与技术根因）+ 模式沉淀入 skills。

## 5. 报告双文档策略
主报告人可读（禁黑词）；门禁 JSON/证据链/rebase 序列/精确栈另行存档（quality/ + 日期目录）。

## 6. 评审裁决
subagent 化评审 + 质疑-裁决（≤2 轮，G 日终兜底）+ 实证定级 + 只读评审纪律。

## 7. Skills 映射
通用：ai-code-review / pj-core / sdlc / router / incident-review / test-naming / error-code / comment-policy / essential-tool-install；新 skill 遵循写作原则（验收清单，不写实现步骤）。\n项目特有 skill/sop 产出到项目根 `skills/` 目录（如 pj-config.md、`<project>-sop`，引用 pj-core §3 接入模型）；跨项目可复用的新纪律回流 Scaffold policies/ 与 skills 仓库（演进双轨，见 README）。

## 8. Token 纪律
见 policies/token纪律.md。

## 9. 日终审核清单（G 用 7 项）
① 逐条 commit log（message 与公示定稿一字不改？）② push 前窗口是否有需插入修改 ③ 门禁证据交叉核验 ④ 遗留/OPEN 项 ⑤ 复盘触发 ⑥ 反哺登记 ⑦ 明日派发。

## 10. 硬约束红线
B 方案 push 规则；熔断（force push/删除/回滚停住）；M0/M1 文字不可动类不可翻案项。

## 11. 归档
旧 SOP 版本保留归档；切换以 G 指令为准。
