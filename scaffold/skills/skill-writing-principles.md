# 新 Skill 写作原则（跨项目公共 SOP）

> 定位：Skill = **防漏网护栏 + 记忆**，不是"实现说明书"。模型能力（设计/判断/方案）留给模型自由发挥；skill 只约束"别漏、别编、别假绿"。

## 1. 允许写的内容（4 类）

| 类别 | 内容 | 例 |
|---|---|---|
| **流程编排**（组织层） | 阶段/角色/交接契约——规定"什么时候产出什么"，不规定"怎么做" | ai-code-review 7 阶段、iso 的 I/S/O 三阶段 |
| **验收面纪律** | 防假绿/防漏网/实证定级/证据链/质疑-裁决/≤2 轮 | 门禁口径唯一（commit==HEAD 且 dirty==0）、实证定级 |
| **产出格式** | finding schema/报告模板/统一字段——可比较、可机器解析 | ai-code-review finding schema |
| **操作型事务清单** | bootstrap 接入/工具安装（该工具是验证唯一途径时） | essential-tool-install 的安装清单、iso operations 的进场清单 |

## 2. 禁止写的内容（3 类）

1. **实现步骤**："先做 A → 再做 B → 用 C 工具"——除非该工具/步骤是**验证的唯一途径**（门禁/证据采集），否则一律不写；实现路径留给执行者自决。
2. **判断路径指定**："怎么找问题""怎么做设计""先考虑 X 再考虑 Y"——判断方法留给模型；skill 只规定**验收结果**（什么算过、什么算漏、什么算假绿）。
3. **结构元说明**：描述"这段与那段的关系""这段在讲什么""看第几行"的句子——见 `policies/constraints-and-criteria.md` §1。SKILL.md 首要读者是模型，为定位而存在的句子对它零增益。

## 3. description（frontmatter）：只写何时用

description = 职责句 + 触发词，**不写流程步骤摘要**（「先…再…」「然后」「第一步」「接下来」接动作的摘要）——agent 读到摘要会照它执行而不读正文（行为假设，记验证债，见 §4 自检问法）。范式不变：不改成纯触发式（"Use when…"），职责句保留。阶段命名链不是步骤摘要——`iso` 的「Insight → Strategy → Operation」即误伤样本，裸 → 不在此列。lint 对序列词告警（warning 级），见 `scaffold/skill-lint.py` 检查项 1。

## 4. 判定自检（写每条时过一遍）

- **删掉这条，模型会不会漏网/假绿/编造？** → 会 = 验收面纪律，必须留
- **删掉这条，模型还能不能自由发挥？** → 不能 = 该条目在教"怎么做"，删 / 降级为 references 按需读（方法框架允许进 references，不强制加载）
- **这条是流程编排还是实现步骤？** → 流程编排留（组织层）；实现步骤删
- **删掉这句，模型的行为会变吗？** → 不变 = 结构元说明，删

## 5. 分层存放

- **验收纪律 + 产出格式** → 主 SKILL.md（触发即生效）
- **方法框架/可选流程**（如 TDD 循环、spec 驱动）→ references/ 按需读——不强制加载，不占主上下文

## 6. 边界

- 省 token 不降交付标准；约束只砍"错误"，不砍"能力"；
- 外部引入的 method-type skill（如 ad-* 系列）按需引用为方法框架，同域优先自有验收型 skill。
