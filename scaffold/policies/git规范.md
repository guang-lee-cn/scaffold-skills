# Git 规范

> 提交信息的格式细节见 `pj-core/references/commit.md`；本文件只管放行单位与边界。

## 粒度

一个 commit = 一个可独立回滚的完整修改。判据只有一条：`git revert <sha>` 之后仍能构建、相关用例仍过。

不混装：格式化 / 重构 / 功能 / 测试修复分开提交，代码与文档分开提交。

## 放行单位

push 以「一个完整工作单元」为单位：一张卡或一个任务，评审通过、门禁绿、工作树干净 → 一次 push。

不逐 commit 推，也不攒跨单元大批——攒成大批说明单元拆错了，改拆卡。

## 历史

只增不改：已经进入评审或已经推送的 commit，一律不重写（amend / rebase / drop 都不做），要改就补新 commit。

确需重写历史时停手，记入问题台账，不在执行期自行处理。

## 编号

公共仓库里不带任何内部编号。编号只对内部台账与复盘有意义，对读代码的人是噪音。

- commit message、代码注释、测试名：不出现台账编号、卡片编号、决策编号
- 例外只有一个：缺陷已登记进**公司级故障编码系统**时，提交正文带一行 `Fault: <公司编码>`
- 公司编码的格式由公司系统定义，本文件不规定也不校验；未接入系统前这行不写

## 禁止

- 禁 AI 工具署名（`Co-Authored-By`、生成器名称等）
- 禁协作元信息：「产物移出版本库 / 工作区不再变脏 / QA 取阅」这类治理说明不进提交信息——治理事实落 `.gitignore` / 脚本头部 / README
