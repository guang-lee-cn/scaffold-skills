# Git 规范（粒度 / 放行 / 历史）

> 提交信息的格式（type 枚举、正文、编号、署名）见 `commit-messages.md`，本文件不重复。

## 粒度

一个 commit = 一个可独立回滚的完整修改。判据只有一条：`git revert <sha>` 之后仍能构建、相关用例仍过。

不混装：格式化 / 重构 / 功能 / 测试修复分开提交，代码与文档分开提交。

**中间态可构建**：删字段 / 改签名 / 删枚举的那次提交，必须同时带上它打破的用例改判。判据不是「分支头能编」，而是**每个提交单独能编**。做不到说明这次改动该拆成两个提交，而不是把用例推到下一个提交。

## 放行单位

push 以「一个完整工作单元」为单位：一张卡或一个任务，评审通过、门禁绿、工作树干净 → 一次 push。

不逐 commit 推，也不攒跨单元大批——攒成大批说明单元拆错了，改拆卡。

**push 是唯一的对外放行点，因此不是机械动作**：缺独立评审记录的工作单元不得 push，架构师自评审不能替代独立评审。

## 历史

只增不改：已经进入评审或已经推送的 commit，一律不重写（amend / rebase / drop 都不做），要改就补新 commit。

确需重写历史时停手，记入问题台账，不在执行期自行处理。

**唯一例外**：只改消息、不改树的 amend 允许，前提是先确认没有任何 run 的 `summary.json.git.commit` 指向它——被归档证据钉住的提交，改消息也会让证据链悬空。
