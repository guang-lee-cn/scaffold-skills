# 跨环境文件操作与命令执行

> 环境类型从 `pj-config.md` 的「环境类型」读取：`wsl2` / `linux-desktop` / `ssh-remote`。
> 通用原则所有环境一致；分支只写各环境的通道细节。

## 1. 通用原则

1. **通道选择**：能直写就直写；失败**换通道**，不反复重试同一失败通道（同一动作失败两次就换命令/目录/通道）
2. **命令执行边界**：分清「agent 所在机」与「目标机」——本地 shell 只跑本地命令，目标机命令一律走对应通道
3. **路径**：绝对路径；含中文/空格路径经变量或文件传递，不做 shell 拼接转码
4. **编码**：UTF-8；验证用**目标系统读取**，防本地显示乱码误判
5. **长操作**：声明时长 + 阶段心跳；超过 30 分钟的外部等待不轮询，等通知

## 2. `wsl2`（Windows + WSL 混合）

背景：文件工具对 `\\wsl.localhost\...`（9P 挂载）支持不完整，表现为 I/O error 或 mtime 异常。

| 操作 | 做法 |
|---|---|
| 读 WSL 文件 | UNC 只读优先；失败回退 `wsl.exe cat` |
| 搜索 WSL 文件 | 同上，回退 `wsl.exe grep` |
| 写 WSL 文件 | **不 UNC 直写**：写 Windows Temp → `wsl.exe cp` → WSL 侧处理 |

核心：**UNC 只读、写必桥接**。中文路径经变量传参——`wsl.exe` 命令行里的中文转码会静默失败，命令无输出就先怀疑转码。

## 3. `linux-desktop`

无桥接问题，全部直接本地路径与本地命令。长任务用 `nohup ... &` 或后台任务；编码用 `file -bi` 复核。

## 4. `ssh-remote`

| 场景 | 做法 |
|---|---|
| 文件传输 | 写远端 = 本地 Temp → `scp`（单文件）/ `rsync -az`（批量）；读远端 = `scp` 或 `ssh cat` |
| 命令执行 | 一律 `ssh <host> "cmd"`；批量走一次 heredoc/脚本，减少往返 |
| 长任务 | `nohup cmd > log 2>&1 &` + 日志轮询；断线恢复用 `tmux` / `screen` |
| 权限 | key 认证；非必要不 sudo；禁明文口令 |
| 路径/编码 | 远端绝对路径；本地与远端路径不混用；`file -bi` 校验 UTF-8 |

核心：**SSH 是唯一命令入口**，不绕行 GUI 远程桌面做文件操作。

## 5. 切换环境

改 `pj-config.md` 的环境类型 → 按本文件对应分支执行 → 重录该环境的已验证命令基线。
