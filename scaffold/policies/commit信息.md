# 提交信息（唯一权威）

> 提交信息的格式只在本文件定义。其他地方（角色规范、项目工程流程、技能）只许引用，不许复制——复制即分叉，实测已经分叉过三次（类型列表差一项、正文要求用了已废止的编号、状态枚举写成数字）。

## 1. 格式

```
<type>(<scope>): <做了什么>

1. <改动>
2. <改动>——<为什么，只有不显然的才写>

验证：<用例名>（回退则红）   # 仅 fix
Fault: <公司编码>            # 仅当已登记进公司级故障编码系统
```

- 标题 **≤72 字符**，祈使句，句末不加句号，只写做了什么、不写理由
- **结构是三段：总述（标题）→ 分条列点 → 需要时加 trailer**。正文不做小作文
- **一条一句**：分条里换行的长句直接判不合格——句子长说明没想清楚，拆开或删掉
- **分条 ≤4 条，正文 ≤10 行**。超过说明这个提交在做多件事：它是提交粒度信号，拆提交，不是删字
- 正文编号分条，一条一个改动；空正文不合格（`Merge` 自动生成的除外）
- 正文只写 what / why，不写 how（命令、工具、环境细节进工作记录）
- 自检标准：陌生人 30 秒读懂

## 2. type 枚举（冻结）

`feat` / `fix` / `refactor` / `test` / `style` / `chore` / `merge`

- `style` 只允许格式化工具的输出。格式化顺带逼出的结构改动（抽函数以避免不可读阶梯）可以在同一提交里做，但正文必须点名「哪一处是结构调整、为什么格式化做不到」
- `merge` 是合并提交专用。合并提交的标题长度上限同样是 72，不豁免
- 自造 type 需要改本文件并说明理由，不许在提交里悄悄出现

**scope** 由项目声明（`pj-config.md` 的 scope 表），此处不预设。scope 用短名，不接受全路径。

## 3. 编号、代号与署名

- **内部编号默认不带**：台账编号、卡号、决策编号、run id、变异编号只存在于内部文档，公共仓库里没有解码表
- **标题里一律不带代号**，包括阶段 / 批次 / 里程碑代号（`EP-xx`、`S3`、`M2`）：标题是给没有解码表的人看的第一行，写成「这次改动做了什么」
- **黑话与隐藏背景同样禁止**：需要读者先知道内部上下文才能解开的词（内部隐喻、项目自造简称、只有团队懂的缩写）不进提交信息。判据是「陌生人 30 秒读懂」，不是「团队读得懂」
- 唯一例外：缺陷已登记进**公司级故障编码系统**时写一行 `Fault: <公司编码>`；格式由公司系统定义，本文件不规定也不校验，未接入前不写
- **禁止 AI 工具署名**（`Co-Authored-By`、生成器名等）
- **禁止协作元信息**：「产物移出版本库 / 工作区不再变脏 / QA 取阅」这类治理说明不进提交信息，治理事实落 `.gitignore` / 脚本头部 / README
- 门禁数据归档提交（`chore` 类）允许在**正文** trailer 写 run id 与 commit：归档的用途就是记录哪一轮、哪个 commit 上的结果，禁掉会让证据只能靠位置隐含。标题仍不写

## 4. 示例

```
feat(core): stop double-completing a late reply

1. complete_reply 的 Pending→Replied 改 CAS，迟到回复只加计数
2. pending 表加 late_reply 计数——原先迟到与丢失现象相同，无法区分

验证：LateReplyAfterTimeoutIsDropped（回退 CAS 则用例红）
```

```
chore(quality): archive the gate run from the merged tree

Run: EP-05-20261025T183820Z
Commit: daafe8a20
Result: 10/10 PASS
```

## 5. 判定

机械判据已经落地：`quality/commit-lint.sh`（bootstrap 会装成 `.git/hooks/commit-msg`）。它管能管的部分——type、标题长度、分条数、正文行数、AI 署名、内部代号。**它管不了的部分靠下面三条自检**：

1. 标题去掉后，正文能不能独立说清这个提交做了什么
2. `fix` 有没有一行「回退则红」的用例
3. 提交信息里有没有「团队读得懂、陌生人读不懂」的词

为什么要有脚本：这条规则违规四次、涉及十一个提交，全部是人工事后发现——**规则没进执行路径，就等于没有规则**。写进策略文件的规则迟早会被上下文压缩挤掉，装在 commit-msg 钩子里的不会。
