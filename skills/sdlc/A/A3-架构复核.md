# A3 · 架构复核

> 归属：`sdlc/A/`　版本：v0.1（2026-10-17）
> 上游：**A2 架构方案** + **S5 差异矩阵**　下游：**I1 基线锁定**
> 定位：本卡是**进入实现前的最后一道闸**。

## 1. 输入

| 参数 | 来源 | 必填 |
|---|---|---|
| 架构文档 | A2 | 是 |
| 差异矩阵（四列） | S5 | 是（有规范时） |
| 冻结基线 | R4 | 是 |
| 代码事实 | 仓库 | 是 |

## 2. 目标

判定「方案能不能按预期高质量实施」，输出**偏差项 + 处置**，不是形容词式的"基本合理"。

## 3. 五个复核维度（缺一即漏）

| # | 维度 | 判据 | 常见偏差 |
|---|---|---|---|
| 1 | **MVP 目标有无偏差** | 与 R4 冻结基线逐条比对 | 范围悄悄扩大；"二期"含糊 |
| 2 | **架构设计合理性** | 组件可追到需求或规范条款；无孤儿 | 组件凭空出现 |
| 3 | **自研核心层合理性** | 能回答「三问」（见 A2） | 伪分层 |
| 4 | **规范一致性** | 与 S5 差异矩阵一致，无矛盾陈述 | 文档 A 处说 Basic、B 处产物是 Enhanced |
| 5 | **证据充分性** | 每条带 `(A?,B?)`；B3 占比已知 | 全靠 B1/B2，B3 = 0 |

> **非功能评审节点**：接口/契约冻结前，按 `ai-code-review/references/dimensions.md` 强制过 ABI/可观测/容量/稳定性四维（未过不得冻结，阻塞项记 P1）——维度 2 的补充闸，不新增复核维度

## 4. 步骤

| # | 动作 | 判据 |
|---|---|---|
| 1 | 逐维度过一遍，记录偏差 | 五维度全覆盖 |
| 2 | **每个偏差项标注证据等级** | `(A?,B?)` |
| 3 | 区分：范围问题 / 进度问题 / 事实错误 | 无"待定"糊弄 |
| 4 | 给处置建议 + 指定批准人 | 无空缺 |
| 5 | 输出复核报告 | — |

## 5. 输出

`架构复核报告`：
- 五维度结论表（通过 / 有偏差 / 阻塞）
- 偏差项清单（`ID / 描述 / 证据 / 分级 / 处置 / 批准人`）
- **不修改被复核文档**，订正建议单列

## 6. 退出条件 DoD

- [ ] 五维度全部过完，无跳过
- [ ] 每条偏差有 `file:line` 或规范章节号
- [ ] 无"待定""应该没问题"
- [ ] 未修改被复核对象

## 7. 反例

- ❌ 复核 = 夸一遍 ⇒ 复核的价值在挑错
- ❌ 复核时顺手改原文 ⇒ 复核与修改混同，失去参照系
- ❌ 用"整体合理"掩盖具体偏差 ⇒ 不可处置
