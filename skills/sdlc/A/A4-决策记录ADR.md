# A4 · 决策记录 ADR

> 归属：`sdlc/A/`　版本：v0.1（2026-10-17）
> 上游：全流程（任何需要拍板的点）

## 1. 输入

| 参数 | 来源 |
|---|---|
| 待拍板问题 | 任一阶段 |
| 候选方案 | 提出者 |

## 2. 目标

把关键决策**连同否决的方案**一起记下来，避免三个月后重新争论。

## 3. ADR 必备字段

| 字段 | 要求 |
|---|---|
| 编号 / 标题 | 唯一 |
| 状态 | 已确认 / 待决策 / 已作废 |
| 背景 | 决策所依据的事实（带证据） |
| 候选方案 | ≥2 个，含被否决的 |
| 决策 | 选了哪个 |
| 理由 | 为什么选它、为什么否决其余 |
| 后果 | 引入的代价与后续动作 |
| **批准人** | 空缺即为未拍板 |

## 4. 输出

`ADR 条目` —— 落进架构文档 §ADR 段，或独立 `adr/` 目录。

## 5. 退出条件 DoD

- [ ] 关键决策点已识别（不是全部都记，只记会反复被问的）
- [ ] 每条含被否决方案与理由
- [ ] 批准人字段无空缺

## 6. 反例

- ❌ 只记决策不记理由 ⇒ 无法复核
- ❌ 被否决方案不写 ⇒ 下次重提，重复争论
- ❌ 批准人留空当已决 ⇒ 假共识
