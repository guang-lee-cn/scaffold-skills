# A · 架构设计

> 归属：`sdlc/A/`　阶段定位：**把需求与规范约束变成可实施的架构方案**
> 上接：**S5 差异矩阵**（有规范时）／ **R4 冻结基线**　下接：**I 实现**

## 1. 卡片清单

| # | 卡 | 输入 | 输出 | 状态 |
|---|---|---|---|---|
| **A1** | MVP 定界 **【参数化】** | shall 总数 / 工作包 / **周期 / 人力 / 合规口径 / 风险容忍** | MVP 范围 + 裁剪清单 + 每项的批准人 | ✅ |
| A2 | 架构方案 | MVP 范围 | 架构文档（组件/接口/数据流/状态机） | ✅ |
| A3 | 架构复核 | 架构文档 + 规范 | 复核报告（偏差项 + 处置） | ✅ |
| A4 | 决策记录 ADR | 关键决策点 | ADR 条目（背景/决策/理由/后果） | ✅ |

### ⭐ A1 的必填参数（缺一不可）

| 参数 | 为什么必须 |
|---|---|
| `周期` | 决定能装下多少工作包 |
| `人力` | 决定并行度 |
| `合规口径` | 决定"规范缺失项"是 P0 还是可接受裁剪 |
| `风险容忍` | 决定未定项（A6）是排期补还是书面接受 |
| `shall 总数` | 分母；不穷举则"覆盖率"无意义 |

> **缺周期/人力 ⇒ A1 只能出候选集，出不了唯一 MVP。**

## 3. 复核维度（A3 用，缺一维度即漏）

| # | 维度 | 判据 |
|---|---|---|
| 1 | MVP 目标有无偏差 | 与 R4 冻结基线逐条对 |
| 2 | 架构设计合理性 | 组件能追到需求或规范条款 |
| 3 | 自研核心层合理性 | 分层的**依据**是否成立，而非"看起来分层了" |
| 4 | 规范一致性 | 与 S5 差异矩阵一致 |
| 5 | 证据充分性 | 每条结论带 `(A?,B?)`；B3 占比 |

## 5. 反例

- ❌ 无参数就定 MVP ⇒ 范围不可控，后期必然砍功能
- ❌ 裁剪项无批准人 ⇒ 合规责任落空
- ❌ 把"偏离"写进"自研增强" ⇒ 缺陷被美化成特性
