# V · 验证

> 归属：`sdlc/V/`　阶段定位：**证明它真的能跑，且证明方式是别人能复现的**
> 上接：**I3**　下接：**D 交付**

## 1. 卡片清单

| # | 卡 | 输入 | 输出 | 状态 |
|---|---|---|---|---|
| V1 | 复现 | 问题报告 | 可复现步骤 + 实际观测 | 待补 |
| **V2** | 定界 | 复现结果 | 根因定位（`file:line`）+ 定界结论 | 待补 |
| V3 | gtest | 定界结论 | 回归测试用例（先红后绿） | 待补 |
| V4 | 回归 | 改动后代码 | 全量测试通过记录 | 待补 |
| **V5** | 独立复核 | 全部产出 | 复核报告（无实现包袱的第三方视角） | 待补 |

## 2. ⭐ 两条硬纪律

1. **先定界后修法**（V2）：**禁止**用「改断言 / 改期望」让测试变绿。
   > 测试变绿不等于缺陷消失，只等于断言被放宽。
2. **完成声明门禁**：无**新鲜 RUN 证据**不许声称完成。
   > 见 `../../pj-core/SKILL.md` §Iron Law。

## 5. 退出条件 DoD

- [ ] 问题有可复现步骤，且他人可执行
- [ ] 根因定位到 `file:line`，非猜测
- [ ] 回归测试先红后绿（有记录）
- [ ] 全量回归通过
- [ ] 独立复核报告已出

## 6. 反例

- ❌ 改断言让测试变绿 ⇒ **最危险的失效模式**
- ❌ "应该没问题"当验证 ⇒ 不可复现
- ❌ 跳过独立复核 ⇒ 自我确认偏误
