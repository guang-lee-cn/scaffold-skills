# sdlc · 需求→交付 7 段阶段链（v0.4）

> **SDLC = Software Development Life Cycle**（软件开发生命周期）。
> 命名取「研发阶段」之意，与仓库既有的**来源轴**（`vendor/`、`agent-skills/`）、**领域轴**（`domains/`）区分。

## 一、⭐ 定位澄清（易错，务必先读）

本链**不是**替代 `iso/`，而是**在它之上加一层组织**：

| 层 | 是谁 | 回答什么 |
|---|---|---|
| **组织层**（本目录） | `sdlc/R\|S\|A\|I\|V\|D\|P/` | **什么时候做、产出落到哪** |
| **方法内核**（既有） | `iso/`（Insight/Strategy/Operation，Heavy+Light） | **怎么做** |
| **协作元层**（既有） | `pj-core/`（门禁/纪律/模板/桥接） | **与人怎么协作** |

> ⚠️ **订正**：曾误判「仓库缺阶段轴」。实际 `iso/` 就是一条成熟的三阶段工作流
> （带门禁、强制产出、回滚机制、四条不变量）。**真实缺口不是"没有阶段轴"，而是：**
> ① **缺「规范对齐（S）」这一段**（iso 三阶段没有对应位置）；
> ② 既有阶段（R/A/I/D）散落在不同顶层目录，**没有统一组织**。

## 二、三轴正交

| 轴 | 回答 | 落点 |
|---|---|---|
| **阶段轴**（本目录） | 什么时候做 | `sdlc/R\|S\|A\|I\|V\|D\|P/` |
| **来源轴**（既有） | 自研 / 第三方 | `vendor/`、`agent-skills/` |
| **领域轴**（既有） | 什么技术域 | `domains/`（原 `ros2/`） |

> 三轴各自正交，交叉处才是一个具体技能。**不要把方法内容塞进阶段目录。**

## 三、7 段 26 卡

```
R 需求挖掘 → S 规范对齐 → A 架构设计 → I 实现 → V 验证 → D 交付 → P 复盘
```

| 段 | 卡 | 状态 |
|---|---|---|
| **R** 需求挖掘 | R1 采集与结构化 / R2 分级与证据绑定 / R3 需求-风险联动 / R4 冻结与变更 | 占位 |
| **S** 规范对齐 | S1 规范身份核验 / S2 官方架构抽取 / S3 shall 清单 / S4 工作包聚类 / S5 差异矩阵 | ✅ **已落 5 卡** |
| **A** 架构设计 | A1 MVP 定界【参数化】 / A2 架构方案 / A3 架构复核 / A4 决策记录 ADR | 占位 |
| **I** 实现 | I1 基线锁定 / I2 修改方案（含下探论证） / I3 小步实施 | 占位 |
| **V** 验证 | V1 复现 / V2 定界 / V3 gtest / V4 回归 / V5 独立复核 | 占位 |
| **D** 交付 | D1 小步推送 / D2 出库发布 / D3 文档同步 | 占位 |
| **P** 复盘 | P1 故障复盘 / P2 沉淀回台账 / P3 skill 反哺 | 占位 |

## 六、调用约定

1. **按阶段调用，不要求全链跑通。** 缺参数写「未定」，**不许猜**。
2. **证据分级是硬要求**：任何产出表每一行带 `(A?,B?)`。
3. **先定界后修法**（V2）：禁止改断言让测试变绿。
4. **每阶段结束写交接块**：STATE + EVIDENCE + OPEN + RISK（见 `_shared/handoff-protocol.md`）。
5. **P3 反哺**：每次真实用例后把坑回写进对应卡的「反例」栏。
