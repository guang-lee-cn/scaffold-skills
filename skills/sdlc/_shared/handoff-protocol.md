# 多模型 / 多 agent 交接协议（跨阶段共用）

> 作用：让任务在不同执行者之间**可续跑**。核心不是格式，是**不让下一个人靠猜**。
> 版本：v0.1 草案（2026-10-17）

## 为什么需要

多模型协作的真实失败模式不是"模型能力不够"，而是：
- 下一个人**不知道上一个人验证到哪**，重复跑一遍
- **未决项被当成已决项**（上一个人标"待确认"，下一个人当默认）
- 证据不可复现 ⇒ 下一个人无法证伪，只能重信

## 交接块（每阶段结束必须写）

```markdown
## 交接 · <段码> <阶段名> · <日期>

**STATE（做到哪）**
- 已完成：<具体动作 + 产物路径>
- 进行中：<做到哪一步>
- 未开始：<明确列出>

**EVIDENCE（可复现证据）**
```bash
# 命令 + 期望输出
```

**OPEN（未决项，谁拍板）**
| # | 问题 | 卡住什么 | 谁决定 | 默认（未回复时怎么办） |
|---|---|---|---|---|

**RISK（已知风险）**
| 风险 | 影响 | 当前缓解 | 触发升级的条件 |
|---|---|---|---|
```

## 三条硬约束

1. **STATE 不许写"基本完成""大部分"**。要么有产物路径，要么写未完成。
2. **EVIDENCE 必须是真跑过的命令**。纸面校验 ⇒ 下一个人会重复踩坑。
3. **OPEN 每一项必须有默认动作**。否则交接等于阻塞。

## 接手方职责（3 步）

1. **先验证据**：跑一遍 EVIDENCE 里的命令，确认与描述一致。不一致 ⇒ 停下来问，不要"先往下做"。
2. **再看 OPEN**：确认未决项是否已被拍板；未拍板 ⇒ 用默认动作，并记录。
3. **接管后重写交接块**：不要在上一个人块上追加，容易丢上下文。

## 反例

- ❌ 在旧交接块上追加 ⇒ 上下文丢失，后面的执行者读不到前面
- ❌ OPEN 项无默认 ⇒ 交接即阻塞
- ❌ EVIDENCE 写"见上文" ⇒ 不可复现
- ❌ 多个执行者同时写同一个文件 ⇒ 互相覆盖（必须先锁定归属）
