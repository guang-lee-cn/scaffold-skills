# S2 · 官方架构抽取

> 归属：`sdlc/S/`　版本：v0.1（2026-10-17）

## 1. 输入

| 参数 | 来源 | 必填 |
|---|---|---|
| 规范原文（normative） | S1 产出 | 是 |
| Machine Readable Files（若有） | S1 产出 | 否（有则优先） |

## 2. 目标

从规范**反推出**架构：有哪些组件、组件间什么接口、数据怎么流、状态怎么变。

## 3. 步骤

| # | 动作 | 判据 |
|---|---|---|
| 1 | 取 S3 的 shall 清单 | 清单齐 |
| 2 | 按 **shall 的主语**聚类 ⇒ 候选组件 | 每个组件 ≥1 条 shall |
| 3 | 按 **shall 的宾语**连线 ⇒ 候选接口 | 每条跨组件 shall 对应一条接口 |
| 4 | 用规范自带图/表交叉验证 | 图与推導一致，或已记下差异 |
| 5 | 列「无归属 shall」 | 数量 = 0，或逐条已定性 |

### ⭐ 核心方法：从 shall 反推，不从目录反推

> **目录是作者的组织方式，不是架构。**
> 照抄目录会得出"规范没有架构"的错误结论。

## 4. 输出

`官方架构卡`——组件清单 / 接口清单 / 数据流 / 状态机，每项带章节出处 + `(A?,B?)`。

## 5. 退出条件 DoD

- [ ] 每个组件能追到 ≥1 条 shall
- [ ] 无归属 shall 数为 0，或已逐条定性为「跨组件 / 理解存疑 → A6 未定」
- [ ] 与规范自带图/表做过交叉验证

## 6. 反例

- ❌ 凭目录抽架构
- ❌ 把「规范未提及但我们知道有」的东西写成规范组件 ⇒ 应标 A4 自研增强
- ❌ 组件之间没有接口，但数据流上又互相调用 ⇒ 组件边界画错了

## 7. 自检命令

```bash
# 抽所有 shall 的主语（前 8 个词），人工聚类
grep -o '[^.]*\bshall\b[^.]*\.' "$SPEC_PATH" | awk '{print $1, $2, $3}' | sort | uniq -c | sort -rn | head -30
```
