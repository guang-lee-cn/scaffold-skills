# S3 · shall 清单（义务穷举）

> 归属：`sdlc/S/`　版本：v0.1（2026-10-17）

## 1. 输入

| 参数 | 来源 | 必填 |
|---|---|---|
| `SPEC_PATH` 规范原文 | S1 | 是 |
| 章节 normativity 表 | S2 | 是 |

## 2. 目标

穷举规范里的**合规义务**，作为后续所有比对与验收的唯一尺子。

## 3. 步骤

| # | 动作 | 判据 |
|---|---|---|
| 1 | 全文计数 `shall`（两种口径） | 两数一致 |
| 2 | 按章节切分，标每章 normative / informative | 每章已标注 |
| 3 | 只保留 normative 章节里的 shall | 剔除了示例段 |
| 4 | 逐条记录：章节号 + 原文摘录 + 义务对象 | 每条三项齐全 |
| 5 | 标注每条的 `(A?,B?)` | 全部已标 |

### ⭐ 两条已知坑

1. **`shall` ≠ 义务**："shall be able to" 是能力陈述，不是对实现的硬性要求。
2. **章节 normativity 决定效力**：normative 附录里的 shall 才算数；
   示例 / informative 章节里的 shall **不计入义务**。

## 4. 输出

`shall 清单表`：`序号 / 章节号 / 原文摘录 / 义务对象 / (A?,B?)`

## 5. 退出条件 DoD

- [ ] 两种计数口径结果一致（不一致 ⇒ 切分逻辑有问题）
- [ ] 每条含章节号 + 原文摘录
- [ ] 已剔除 informative 章节
- [ ] 每条已标 `(A?,B?)`

## 6. 反例

- ❌ 把 `should` / `may` 写进验收标准 ⇒ **只有 `shall` 是合规义务**（RFC 2119）
- ❌ 不区分章节 normativity 就计数
- ❌ 用"应该有""大概要"当义务 ⇒ 只能是 A6 未定

## 7. 自检命令

```bash
# 两种口径必须一致
a=$(grep -c '\bshall\b' "$SPEC_PATH")
b=$(grep -o '[^.]*\bshall\b[^.]*\.' "$SPEC_PATH" | wc -l)
echo "总行计数=$a  按句计数=$b"; [ "$a" = "$b" ] && echo OK || echo MISMATCH
```
