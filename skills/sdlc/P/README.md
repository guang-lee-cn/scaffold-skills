# P · 复盘

> 归属：`sdlc/P/`　阶段定位：**把付过的学费变成"不再重演"的机制**
> 上接：**D3**　下接：回到 **R**（下一轮）

## 1. 卡片清单

| # | 卡 | 输入 | 输出 | 状态 |
|---|---|---|---|---|
| **P1** | 故障复盘（九段式） | 事故 / 缺陷 | 复盘报告（根因分层 + 改进措施闭环） | 待补 |
| P2 | 沉淀回台账 | 复盘报告 | 台账条目（已知遗留问题表） | 待补 |
| **P3** | skill 反哺 | 踩到的坑 | 对应阶段卡「反例」栏的更新 | 待补 |

## 2. ⭐ P3 是整个链路的闭环点

> **没有 P3，skills 仓库就只是文档，不会变好用。**
> 每次真实用例后，把新踩到的坑回写进对应卡的「反例」栏——
> 反例栏空的卡 = 没承载过真实用例 = 未验证。

## 3. 方法内核 / 既有资产

| 资产 | 路径 | 提供什么 |
|---|---|---|
| 事故复盘纪律 | `../../review/incident-review/SKILL.md` | 九段式复盘 |
| 问题四分类 / 复盘模板 | `../../pj-core/references/issues.md` | |

## 4. 退出条件 DoD

- [ ] 复盘报告含根因分层（不是"改了就好"）
- [ ] 改进措施有闭环（负责人 + 时间）
- [ ] 已回写台账
- [ ] 已反哺 skill 反例栏

## 5. 反例

- ❌ 复盘 = 写报告 ⇒ 产出是"不再重演"，不是文档
- ❌ 只修不复盘 ⇒ 同类问题换个地方再犯
- ❌ 复盘不反哺 skill ⇒ 学费白付
