# 8 大思考接口（research 详版）

> 属 `skills/research/`（入口与硬纪律在 [../SKILL.md](../SKILL.md)）；本文件是各接口的操作步骤与模板，按需读。

## 接口1：三维度验证

**接口定义：** 理论 + 实践 + 工具 = 完整理解

**操作步骤：**

1. **理论维度**
   - 设计原理是什么？
   - 标准规范是什么？
   - 实现机制是什么？

2. **实践维度**
   - 实际如何使用？
   - 常见问题是什么？
   - 典型场景有哪些？

3. **工具维度**
   - 如何调试？
   - 如何诊断？
   - 如何验证？

**应用示例：system() 研究**
- 理论：三层进程结构、信号处理机制
- 实践：代码示例、故障场景
- 工具：strace、gdb、pstree 等调试工具

## 接口2：渐进式深度

**接口定义：** 入门级 → 原理级 → 故障级 → 工程级

**操作步骤：**

1. **入门级**
   - 这个东西是什么？
   - 基本怎么用？
   - 和其他方案对比如何？

2. **原理级**
   - 内部如何实现？
   - 为什么这样设计？
   - 核心机制是什么？

3. **故障级**
   - 会出什么问题？
   - 为什么会出问题？
   - 如何解决问题？

4. **工程级**
   - 生产环境如何使用？
   - 如何保证安全和性能？
   - 现代架构如何适配？

**应用模板：**
```markdown
## 第X章：[主题]（[难度等级]）

### X.1 [主题] 是什么（入门篇）
- 场景介绍
- 基本使用
- 方案对比

### X.2 [主题] 内部机制（原理篇）
- 实现原理
- 代码流程
- 关键机制

### X.3 [主题] 会出什么问题（故障篇）
- 单线程问题
- 多线程问题
- 竞争条件

### X.4 如何正确使用（工程篇）
- 最佳实践
- 安全考虑
- 性能优化
```

## 接口3：多视角验证

**接口定义：** 用户视角 + 开发者视角 + 架构师视角 = 全面覆盖

**操作步骤：**

1. **用户视角**
   - 用户体验如何？
   - 响应是否及时？
   - 错误提示是否清晰？

2. **开发者视角**
   - API 是否易用？
   - 文档是否完善？
   - 常见陷阱有哪些？

3. **架构师视角**
   - 设计是否合理？
   - 扩展性如何？
   - 维护成本如何？

**检查清单：**
- [ ] 是否考虑了最终用户体验？
- [ ] 是否考虑了业务/产品目标和价值？
- [ ] 是否提供了开发者友好的接口？
- [ ] 是否符合架构设计原则？
- [ ] 是否考虑了可维护性和可扩展性？

## 接口4：问题驱动研究

**接口定义：** 目标与现象 → 原因 → 解决方案 → 预防 = 深度学习

**操作步骤：**

0. **研究目标与成功指标**
   - 这次研究要解决什么核心问题？
   - 预期输出是什么？
   - 成功如何衡量？
   - 有哪些约束条件和假设？

1. **现象识别**
   - 具体表现是什么？
   - 触发条件是什么？
   - 影响范围有多大？

2. **原因分析**
   - 根本原因是什么？
   - 为什么会发生？
   - 相关因素有哪些？

3. **解决方案**
   - 如何临时解决？
   - 如何根本解决？
   - 如何预防再次发生？

4. **预防措施**
   - 如何在设计阶段避免？
   - 如何在代码审查中发现？
   - 如何建立规范和流程？

> 迭代提示：在研究过程中如果发现新的问题或假设，应及时返回“研究目标与成功指标”、“现象识别”或“多视角验证”环节，形成闭环迭代。

**故障分析模板：**
```markdown
## 故障点 [编号]: [名称]（[类型]）

### 现象描述
[具体现象和触发条件]

### 原因分析
[技术原因和根本原因]

### 实际影响
[影响范围和严重程度]

### 解决方案

    // 具体代码解决方案

### 预防措施
- [ ] 设计阶段如何避免
- [ ] 代码审查如何发现
- [ ] 测试如何覆盖
```

## 接口5：技术生态融合

**接口定义：** 单技术 → 技术关联 → 生态融合 = 系统思维

**操作步骤：**

1. **单技术研究**
   - 技术本身如何工作？
   - 核心机制是什么？
   - 优缺点是什么？

2. **技术关联分析**
   - 与哪些技术相关？
   - 会产生什么影响？
   - 如何协同工作？

3. **生态融合考虑**
   - 现代架构如何适配？
   - 云原生环境如何考虑？
   - 未来趋势如何演进？

**生态检查清单：**
- [ ] 是否考虑了容器化环境？
- [ ] 是否考虑了微服务架构？
- [ ] 是否考虑了现代语言特性？
- [ ] 是否考虑了安全性要求？
- [ ] 是否考虑了性能优化？

## 接口6：实战导向工程

**接口定义：** 可用性 + 可维护性 + 可扩展性 = 工程价值

**操作步骤：**

1. **可用性保障**
   - 性能如何？
   - 正确性如何？
   - 稳定性如何？

2. **可维护性提升**
   - 代码是否清晰？
   - 调试是否方便？
   - 文档是否完善？

3. **可扩展性设计**
   - 接口是否合理？
   - 设计是否灵活？
   - 未来是否可扩展？

**工程实践检查：**
```markdown
## 工程实践指南

### 性能考虑
- [ ] 性能测试数据
- [ ] 性能优化建议
- [ ] 性能监控方法

### 可维护性
- [ ] 代码审查模式
- [ ] 调试工具和技巧
- [ ] 文档结构设计

### 可扩展性
- [ ] 接口设计原则
- [ ] 扩展点设计
- [ ] 未来兼容性考虑
```

## 接口7：安全优先工程

**接口定义：** 识别风险 → 理解攻击 → 防御策略 = 安全工程

**操作步骤：**

1. **风险识别**
   - 有哪些安全风险？
   - 风险等级如何？
   - 影响范围多大？

2. **攻击理解**
   - 攻击者如何利用？
   - 攻击路径是什么？
   - 攻击后果是什么？

3. **防御策略**
   - 如何预防攻击？
   - 如何检测攻击？
   - 如何响应攻击？

**安全分析模板：**
```markdown
## 安全风险分析
```

## 接口8：历史演进思维

**接口定义：** 现状 → 原因 → 替代方案 → 未来趋势 = 前瞻思维

**操作步骤：**

1. **现状分析**
   - 当前状况如何？
   - 优缺点是什么？
   - 适用场景是什么？

2. **原因探究**
   - 为什么是这样？
   - 历史原因是什么？
   - 设计考虑是什么？

3. **替代方案**
   - 有什么替代方案？
   - 各自优缺点如何？
   - 如何选择？

4. **未来趋势**
   - 技术如何演进？
   - 需求如何变化？
   - 如何应对？
