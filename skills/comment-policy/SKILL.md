# 注释四分类

## 分类

| 类 | 内容 | 处置 | 依据 |
|---|---|---|---|
| A 契约 | 接口契约标注（@thread-safety/@lifecycle/@qos/@blocking/@scenario）、默认值"为什么"、行为契约 | **保留在头文件** | 删除 = 契约消失；消费方/测试/审核看不到设计文档 |
| B 决策 | "为什么"类（算法选择、顺序依据、防御理由、导出面策略） | **迁移设计文档** | 迁移前提 = 测试已锁定行为（Chesterton's Fence） |
| C 复述 | "what"类（与契约重复、用例名已自明、代码本身已自注释） | **删除** | "别注释显然代码"；靠命名/结构自注释 |
| **D 协作/治理元信息** | git 归属（不入库/忽略说明）、编号黑话引用（J-xx/ADR-xx 无自解释）、QA 取阅/CI 说明、"变脏/挂账/取阅"等协作黑话 | **删除** | 治理事实的声明地是 .gitignore / 脚本头部 / README / 协作文档，不是代码注释；编号引用对阅读者无背景 = 噪音 |

## D 类判定（协作/治理元信息——本项目新增，2026-10-23 实证污染）

代码注释里出现以下即 D 类，**删除**：
- "XX 产物不入 git / 留本地 / QA 取阅 / 移出版本库 / 加忽略 / 工作区不再变脏" —— .gitignore 就是声明地，注释冗余
- "（J-47 纪律）（J-50 同构形态；查询口本批不落，显式挂账）" —— 台账编号无背景 = 黑话；纪律事实在评审文档/设计文档
- "跑完门禁工作区不再变脏" —— 协作黑话
- 处置对照：**A 保留 / B 迁移设计文档 / C 删除 / D 删除（治理事实补 .gitignore 或脚本头部一句话，不写编号）**

## 强制保留面（A 类）

- 版权/许可头（法律要求，非解释性注释）
- 公共 API 契约标注（与项目自身审核必检清单绑定，删了会被打回）
- 默认值的推导依据（容量链/对齐关系，防后人改错无据）
- 行为契约（回调/异常语义，是测试判据来源）

## 决策注释迁移（B 类）——Chesterton's Fence

删除"看似冗余"的注释/校验/逻辑前，**先确认测试已锁定该行为**；未锁定先补测试再迁移，否则行为可能被后人当作冗余移除。

## 复述删除（C 类）

- 与头文件契约重复的实现注释
- 用例名已自注释的体内注释
- 防御注释（代码本身 `if` 判空已自明）
- enum 值旁"合法/非法"等自明注释

## 代码自注释配套

改名让结构自注释（名实相符、成员惯例统一、类型即文档），与注释删除是**配套动作**，不是先删再猜。

## 边界

- "全删"不采纳：契约面与项目自身规范冲突（审核必检清单强制项）。
- @file 头注释保留一行（文件名 + 一句话职责），细节进设计文档。
- 结构自注释可选项（如所有权型 unique_ptr 替代 bool）记录不强制，按简单优先。
