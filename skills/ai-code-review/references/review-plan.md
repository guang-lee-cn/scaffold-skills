# 审查计划模板（P1 产出）

## 1. 范围
- 文件族清单（git 全量 diff 对照——防遗漏：impl/头文件/工具脚本/CI/构建链）
- 排除项（上游文件/生成代码——注明理由）

## 2. 维度（**优先级排序**——Google 8 维度：设计先行）
1. **设计/架构**（最高——主文件先审——大设计缺陷早发现省重写）
2. **契约一致性**（官方语义 vs 实现——本项目红线）
3. **并发/内存安全**（死锁/竞态/UAF——运行期难测需人审）
4. 逻辑正确性（边界/状态/资源）
5. 测试覆盖（正确且充分——审测试本身）
6. 可维护性 / 命名 / 注释（why 而非 what）
7. 文档 / CI 构建链（最低——不阻塞）

## 3. 只读纪律
审查阶段**不可修改任何内容**（代码/文档/配置一律不动）；全部发现输出到报告；修复另起阶段（修改清单门禁）

## 4. 工具基线
- 静态：cppcheck（--version + 完整命令 + suppress 清单——原始输出归档）
- 动态：ASan（-fsanitize=address -fno-omit-frame-pointer）/ TSan（-fsanitize=thread；WSL 需 setarch -R）
- 命令基线存 command-baseline（防环境坑重复踩）

## 5. 出口准则
- P0/P1 清零（或 P0 待实证记录 + 架构师裁决，理由写进评审文件）＋ CI 绿
- P2/P3 记录入台账（不阻塞——拍板项单独列）

## 6. 资源预算
- sanitizer 构建：并行度/耗时/触发时机（本地化 or 常驻——成本硬数据）

## 7. 审查粒度（Google 小变更原则）
- 目标 <400 行 diff / 30 分钟可审——大变更拆批（重构与行为变更分 PR）
- 每次审查 = 一个逻辑单元（不混"重构+新功能+修复"）
