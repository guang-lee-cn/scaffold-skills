ISO Prompt 快捷触发词
=====================

## 阶段触发

| 自然语言                                | 加载的文件                     | 做什么             |
|-----------------------------------------|-------------------------------|--------------------|
| 开始 ISO / 分析需求 / 项目启动          | iso.md                        | 战略洞察（I→S→O）  |
| 开始设计 / 做架构 / 设计接口 / 拆分子系统 | strategy.md                   | 架构设计 + 接口契约 |
| 实现子系统 [名称] / 写代码 / 落地开发   | operations/cpp.md + 子系统契约 | C++ 子系统实现      |
| 集成测试 / E2E / 准备上线               | operations/integration.md     | 集成测试 + 交付     |

## 重构模式

在上述任何触发词前加"重构"二字，AI 会先执行对应文件的重构前置检查：

| 触发                        | 额外执行的检查                               |
|-----------------------------|---------------------------------------------|
| 重构 + 开始 ISO             | 现状评估（架构/痛点/健康资产/触发原因）       |
| 重构 + 开始设计             | 迁移策略 / 向后兼容约束 / 增量替换优先级      |
| 重构 + 实现子系统           | 增量替换模式 / 新旧隔离 / 清理计划            |
| 重构 + 集成测试             | 回归测试 / 对比测试 / 回退切流方案            |

## 并行实现

说"并行实现所有子系统"，主 Agent 会读取迭代计划中的无依赖子系统，拉起多个子 Agent 各自实现。

## 技术深度研究

| 自然语言                            | 加载的文件                            | 做什么                 |
|-------------------------------------|---------------------------------------|------------------------|
| 研究 X / 深度研究 X / 搞懂 X 的原理 | ../research/technical-research-framework.md | 按 8 接口做技术深度研究 |

## 工作流速览

主 Agent: iso.md → strategy.md → 接口契约 + 子系统边界
                                    │
          ┌─────────────────────────┼─────────────────────┐
          ↓                         ↓                     ↓
子 Agent: cpp + 子系统A       cpp + 子系统B         cpp + 子系统C
          ↓                         ↓                     ↓
          └─────────────────────────┼─────────────────────┘
                                    ↓
主 Agent:           integration.md（集成测试 + E2E + 上线检查）
