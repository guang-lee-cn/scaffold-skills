# 集成与验收

> 一句话：**只测契约，失败即停，证据落 run 目录。**

## 1. 三条纪律

1. **只测契约，不测实现**：集成验证子系统之间的接口行为；子系统内部逻辑是单元测试的职责。在集成层重测内部逻辑，等于用最贵的环境跑最便宜的用例。
2. **失败即阻塞**：任一集成用例失败，相关子系统不进下一阶段，直到根因定位。跳过失败项继续集成的，后面每一步都建在错误假设上。
3. **正常关闭路径零残留是干净基线**：偏离基线即回归；确认是既有泄漏的，写明归属判定（见 `scaffold/policies/leak-attribution.md`），不重查。

## 2. 失败四分类（定位责任面，不是穷举）

| 类型 | 判定 | 处理 |
|---|---|---|
| 契约违反 | 行为与契约定义不一致 | 回到实现方修 |
| 契约歧义 | 双方对契约理解不同 | 架构师改契约，双方同步 |
| 环境问题 | 配置 / 依赖 / 端口，非代码 | 修环境重跑，不入台账 |
| 需求遗漏 | 契约未覆盖但业务必需 | 回补契约，不在实现里打补丁 |

不在这四类里的，按同样思路判：**先怀疑契约没把变化点隔住**（改了 A 就得改 B），再怀疑实现。

## 3. 证据

- 测试：命令 + 通过/失败计数 + 失败原文，本次运行
- 性能与资源：命令 + 原始输出，不写"可接受"
- 门禁：run 目录里的 JSON，且 `git.dirty == 0`、commit 与当前 HEAD 一致
- 禁止：截图代替日志、口头描述代替命令、上一轮结果代替本次

## 4. 上线前只问三件事

1. 核心用户旅程有没有一条端到端用例？（不是"测过"，是"有这条用例"）
2. 回退路径是什么、谁按、多久？
3. 出问题的第一眼证据在哪（日志 / 计数 / 返回码）？

答不上来就不用结项，回到对应阶段补。
