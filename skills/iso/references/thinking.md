# references/thinking.md —— 跨阶段通用方法论

> **定位**：跨阶段通用的方法论，设计（strategy）、实现（cpp）、集成（integration）、调试四处共用。
> 本文件当前收录两条：**构造性阶梯法则**（怎么推）与**正交性判据**（怎么切）。
> **性质**：本文件放的是"**如何推理**"的工具，不是流程门禁。铁律区（§0）放的是"不得违反的不变量"。

## 法则（4 句）

1. **最小模型起手**：剥掉非本质变量，只留一个核心变量，先推出一条概念。
2. **每次只加一个变量**：加完判断是**量变**（概念被延伸）还是**质变**（概念被推翻）。
3. **质变即换概念**：旧键作废、重新建模，绝不硬套。
4. **推理失灵切溯因**：无前提（演绎不动）或无样本（归纳不动）时，改用"假设 + 可证伪实验"兜底。

**一句话版**：从最小案例构造，每次加一个变量并验证概念是否质变；演绎/归纳失灵时切到溯因。

## 质变示例（什么时候必须换概念）

需求：给流水线选"因果对齐键"。

- **最小模型（1:1）**：一个输出吃一个输入。`seq`（流内序号）就够——单键可定位。
- **加一个变量（N:1）**：一个输出吃多个输入（如 1 个 Lidar + 10 个 IMU）。`seq` 不是"不够用"，是**概念整个换了种**：从"定位线上的一个点"变成"描述平面上的一个矩形"。单键钉不住矩形，必须升级为 `锚点 seq + stamp 时间窗`。

判定：这是**质变**。若仍硬套单 `seq`，故障链路在扇入处必然对不上。

## 适用点

| 场景 | 用法 |
|------|------|
| strategy.md §6.6 方案对比 | 从最小方案推起，逐步加复杂度，判断方案在质变点是否仍成立 |
| cpp.md 实现 / TDD | 最小实现跑通 → 每次加一个变量 → 质变时停下重构 |
| 调试排障 | 最小复现 + 一次动一个变量；不复现时切溯因（假设 + 可证伪实验） |

## 边界

- 不适用于：无最小模型可建、纯粹涌现/混沌的场景（此时直接走溯因）。
- 与归纳/演绎的关系：归纳需要可重复样本，演绎需要前提；本法则构造最小模型，两者都不需要，是它们的补充。

## 正交性判据

**判据只有一句话**：**改了 A，B 要不要一起改？**

- **要** → A 与 B **不正交**：要么合并职责，要么把共享点提升为**契约**（接口/数据模型），让两边各自独立演进。
- **不要** → 正交，可以放心分开设计和实现。

**四个阶段各自怎么用**：

| 阶段 | 用法 |
|------|------|
| `strategy.md` §6.5 子系统边界 | 划完子系统后**逐对问一遍**。要一起改 → 边界划错了 |
| `operations/cpp.md` §4 抽类 | 两个类总是一起改 → 合并；总是不一起改 → 分开 |
| `operations/integration.md` §5 失败归因 | 一个失败牵动多个子系统 → 先怀疑契约没把变化点隔住 |
| 评审 / 重构 | 判断"这层抽象赚不赚得回它的间接代价" |

> **注意**：正交性是**判据**，不是**结论**。"这个模块耦合度低"这类说法不可证伪，禁止作为文档结论；要写的是**谁会和谁一起改、为什么**（对应 `strategy.md` §11 自检）。
