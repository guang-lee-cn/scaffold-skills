# 架构图格式规范

> 本文件是 `strategy.md` §6 架构设计的图表格式参考手册。AI 绘制架构图时查阅本文，不要在 strategy.md 正文中展开。

---

## 1. 系统分层规则

每个子系统按以下四层组织，依赖方向由外向内：

| 层级 | 职责 | 允许依赖 |
|------|------|----------|
| Interface | 对外暴露API，做协议转换和参数校验 | Application |
| Application | 编排领域对象完成具体用例 | Domain |
| Domain | 核心业务逻辑，零外部依赖 | 无 |
| Infrastructure | 实现接口适配（数据库/网络/外设驱动） | Domain + Application的接口定义 |

**禁止反向依赖**：Infrastructure 不能依赖 Interface，Application 不能依赖 Infrastructure 的具体实现。

## 2. 数据流转图五色规范

| 流类型 | 颜色 | 线条 | 说明 |
|--------|------|------|------|
| 数据流 | 蓝色（#2E86C1） | 实线 | 业务数据/传感器读数/控制指令等有效负载 |
| 控制流 | 橙色（#E67E22） | 实线 | 触发信号/事件/回调等时序控制 |
| 状态流 | 紫色（#8E44AD） | 虚线 | 系统状态/模式切换/心跳等状态信息 |
| 异常流 | 红色（#E74C3C） | 虚线 | 错误码/超时/重试等异常处理路径 |
| 配置流 | 绿色（#27AE60） | 点划线 | 配置文件/参数/初始化数据的加载路径 |

**要求**：图中必须标注颜色对应的流类型。模块用不同背景色区分。

## 3. Mermaid 图类型指引

| 图类型 | Mermaid 语法 | 适用场景 |
|--------|-------------|----------|
| 系统架构/组件关系 | `flowchart TD` 或 `graph TD` | 分层架构图、部署图 |
| 模块间交互/时序 | `sequenceDiagram` | 跨子系统调用顺序 |
| 业务流程/状态流转 | `stateDiagram-v2` 或 `flowchart` | 业务流程图、状态机 |

## 4. 补充图例

| 图类型 | 适用场景 |
|--------|----------|
| 时序图 | 跨子系统交互复杂、调用顺序对正确性有直接影响时补充 |
| 状态图 | 子系统内部状态机复杂、状态转换影响系统行为时补充 |

## 5. 渲染降级说明

Mermaid 对自定义边颜色和 subgraph 背景色的支持因渲染器而异（如 GitHub 的 `mermaid` 滤镜可能不识别 `#2E86C1` 这类自定义色值，`flowchart` 的 `linkStyle` 在多边场景下也有限制）。若实际渲染时自定义颜色不生效，使用以下降级方案：

- 在边的文字标签中追加流类型前缀，如 `-- 数据流 -->` 改为 `-- [D] 数据流 -->`
- 在图的底部添加文字图例，显式说明每种前缀/符号代表的流类型
- 优先保证结构正确，颜色仅作为增强

## 6. Mermaid 渲染规避规则（防报错，强制）

> **每次画图必须遵守**。GitHub / VSCode 等渲染器对部分语法支持不一致，下列写法是实际踩坑后固化的规避项。违反即可能渲染失败。

| # | 规则 | 错误写法 | 正确写法 |
|---|------|---------|---------|
| 1 | **禁止 `&` 多目标** | `A --> B & C` | `A --> B` + `A --> C`（拆两条边） |
| 2 | **边标签用 `|"..."|` 包裹**，标签内不用英文括号、`>`、`<`、`->`、`→` | `|"目标(mesh)"|` | `|"目标"|`（中文括号可用） |
| 3 | **虚线边 `-.text.->` 标签内禁止 `>`**；需虚线时优先 `-.->` 无标签，文字放节点上 | `-.阻塞>3s.->` | `-.->` + 节点标注文字 |
| 4 | **`direction` 只允许在图首行**，subgraph 内禁止 | `subgraph X` + `direction TB` | 去掉 subgraph 内 direction |
| 5 | **节点文本用 `["..."]` 包裹**，避免英文括号；`<br/>` 可用（引号内） | `A[目标(x)]` | `A["目标<br/>说明"]` |
| 6 | **节点 ID 用大写字母或下划线**，不用 `.` `/` `-` | 节点 ID 含 `/` | 节点 ID `FUS`，文本里可含 `/` |
| 7 | **边标签用简短 ASCII**，坐标/箭头用文字代替 | `|"map→odom"|` | `|"map-odom"|` |
| 8 | **优先保证结构正确**，颜色/样式仅增强（渲染器支持差异大） | - | - |

**总体架构图视角约定**：L1 总体架构图**从用户角度出发**，只画用户视角能看到的模块（下发任务、整车、可视化），内部模块是黑盒；内部展开放 L2/L3/L4。
