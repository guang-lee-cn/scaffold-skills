# 基础层选型：自研 vs 开源 vs 复用

> 本文件是 `strategy.md` §6.6 关键决策记录的**选型评估手册**。AI 判断"基础层/公共设施/关键路径"模块该不该自研时查阅本文，不要在 strategy.md 正文中展开。

## 1. 哪些模块必须走这个评估

| 类别 | 判据 | 例子 |
|------|------|------|
| **基础层** | 被 ≥2 个子系统依赖，且不含本项目的业务语义 | 通信传输、序列化、线程池、定时器、日志 |
| **公共设施** | 纯技术能力，换个项目同样成立 | 配置加载、指标上报、错误码框架、CLI 解析 |
| **关键路径** | 出问题会直接违反成功标准或 SLA | 采集/上报通道、调度器、故障恢复逻辑 |

**不属于这三类的（业务逻辑、领域模型、项目特有的编排）默认自研**，不适用本评估——别把这条规则用成"什么都去找开源"。

## 2. 评估维度（每个候选都要过一遍）

| 维度 | 要问的问题 | 不合格信号 |
|------|-----------|-----------|
| 功能覆盖 | 覆盖需求百分之多少？缺口能在外面补吗？ | 核心缺口要改它源码 |
| 许可证 | 与交付形态冲突吗？（静态链接/闭源分发/商用） | GPL 类进闭源交付 |
| 维护活跃度 | 最近一次发布/提交？issue 响应？几个活跃维护者？ | 单人 + 一年无更新 |
| **验证密度（生产验证）** | 被真实世界敲打过多少？证据面：发布年限与版本节奏、下游真实使用（发行版收录/生产案例；star 数不算）、问题单修复与 CVE 处置轨迹、上游自身测试与 CI 状态、我们依赖接口的稳定时长——**≥3 项有据才算「大量验证」** | 只有 demo 和 README；或「各维度突出但没人踩过坑」 |
| 与既有栈的耦合 | 它依赖什么？会把我们锁在某个版本/ABI 上吗？ | 要翻遍我们的 CMake 才能接 |
| 集成代价 | 接入要改多少我们的代码？编译时间/体积涨多少？ | 为接它得重构现有接口 |
| 性能与确定性 | 延迟/抖动/内存满足硬指标吗？**给出的是边界还是均值？** | 只有平均值，没有上界 |
| **替换代价（最常被忽略）** | 将来要换掉它，我们要动多少地方？ | 它的类型渗透进了我们的公共头文件 |

## 3. 判定规则

**优先采用开源**，当且仅当：核心功能覆盖、许可证兼容、维护活跃，且**替换代价被控制在接口层之内**。

**必须自研**（这是正当理由，不要含糊成"想自己写"），满足任一条即可：
- 无候选满足**硬性**指标（实时性、内存上界、确定性延迟）
- 许可证与交付形态根本冲突，且无法隔离
- 需求体量极小（自研总量 < 集成代价），或它本身就是本项目的核心竞争力
- 需要与本项目领域模型深度耦合，外部实现反而阻抗失配

**两者都不成立**（有候选但都有明显缺陷）→ 此时才允许"自研 + 借语义"，并按 §4 记账。

**验证密度阶梯**（核心代码实现的取材优先级）：仓内既有实现 > **大量验证的开源**（验证密度 ≥3 项有据；能引入则引入，硬约束挡着则参考设计再自现）> 低验证但维度突出的候选（开源或自研同理）> 纯自研无参照。后两级允许选，但记**验证债**（§4）：验证密度不足 = 把别人环境里省掉的外部验证时长在仓内重付一遍（补偿测试面：契约全覆盖 + 失败/并发/生命周期/关闭时序路径 + 变异检验 + 消毒器/valgrind + 端到端反证）。大量验证的开源也不是零测试——集成验证照跑，只是不背补偿债。

## 4. 自研必须记账：天花板 + 触发条件 + 升级路径

选择自研时，决策记录里必须写明：

- **天花板**：这套自研实现的能力上界在哪？（例："单机单写者，不支持多写者"）
- **触发条件**：什么情况下会撞到天花板？
- **升级路径**：撞到之后换什么？换的时候要动哪些接口？
- **验证债**：验证密度不足（证据 <3 项）时，补偿测试面清单 + 已还/未还状态；债不阻止选择，只阻止"不说"。

> 自研基础层是一笔**要还的债**。记账不是阻止自研，而是让"以后再说"不会变成"永远不说"。
> 与 ponytail 的 `ponytail:` 注释同一套思路：标记刻意的简化，写明天花板与升级路径。

| 项 | 内容 |
|----|------|
| 模块 | 属于基础层 / 公共设施 / 关键路径中的哪一类 |
| 候选开源 | ≥2 个：名称 + 版本 + 许可证 + 活跃度 |
| 采用 / 不采用 | |
| 理由 | 按 §2 维度逐条对照。**不采用必须写具体技术硬约束** |
| 代价与风险 | 集成代价、版本/许可约束、被淘汰风险 |
| 若是自研 | 天花板 + 触发条件 + 升级路径（§4） |
| 验证密度 | ≥3 项证据逐条指认；不足则列验证债与补偿测试面（§3/§4） |
| 若是采用 | 替换路径：换掉它要动哪里（呼应 §7 接口契约） |
