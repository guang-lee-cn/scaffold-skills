# C++ 语言设施与 clean code 对照

> 本文件是 `operations/cpp.md` §4 与 `light/lang/cpp.md` 的语言级参考：把"手写"换成"标准设施"，能替换就替换。
> 每条都是可判定的——要么能指出替代设施，要么能说明为什么不能替换。

## 1. 用标准设施替代手写

| 手写形态 | 替代 | 判据（出现即替换） |
|---------|------|------------------|
| `const std::string&` 参数被拷贝，或为兼容 C 字符串传 `const char*` | `std::string_view` | 函数内不持有、不修改该字符串 |
| `bool` + 出参、用 `-1`/`nullptr` 表示"无值" | `std::optional<T>` | 返回值可能"没有"，且这不是错误 |
| `tag` + `union`、`enum` + `void*` | `std::variant` | 值在有限若干类型中取其一 |
| 指针 + 长度两个参数 | `std::span<T>` | 只是"一段连续内存"，不涉及所有权 |
| 手写 `for` + 下标做查找/累加/变换 | `<algorithm>`（`find_if`/`accumulate`/`transform`/`any_of`） | 循环体只做单一动作、无副作用交织 |
| 裸 `int` 表示毫秒/秒 | `std::chrono` | 任何时间量 |
| 运行期计算常量 | `constexpr` | 输入在编译期已知 |
| `new` + 手动 `delete`、工厂返回裸指针 | `std::unique_ptr` / `make_unique` | 任何所有权 |
| `+` 链拼接或 `sprintf` 做格式化 | `std::format`（C++20）或既有格式化设施 | 任何格式化 |
| `#define` 常量/函数宏 | `constexpr` / `inline` 函数 / `enum class` | 除非确需条件编译 |

**替换的前提**：不改变可观测行为（生命周期、异常安全、线程安全语义）。若会改变，走 `operations/cpp.md` §6 回滚机制上报，**不自行权衡**。

## 2. 模板的使用规则（三条）

1. **为消除重复而模板，不为"将来通用"而模板**：已有**两个（含）以上具体类型**的调用点才允许模板化；只有一个 → 写具体类型。
2. **约束写成人话**：用 `concept` 或 `static_assert` 给出约束和可读的错误信息，别让调用方读三屏模板报错才能定位。
3. **模板不进公共头文件，除非必要**：模板把实现暴露到头文件，带来编译时间与耦合成本。需要时优先"具体类型 + 内部模板"。

## 3. 注释规则（三条）

1. **解释为什么，不解释什么**：代码说"做了什么"，注释说"为什么这么做"——约束、历史原因、被否决的替代方案。
2. **刻意的简化必须留痕**：为省事而砍掉真实角落的地方（全局锁、O(n²) 扫描、朴素启发式），用注释写明**天花板**与**升级路径**。这与 ponytail 的 `ponytail:` 注释约定、以及 `oss-adoption.md` §4 的"自研记账"是同一条思路。
3. **过期注释按缺陷处理**：改代码必须同步改注释；发现注释与代码不一致，先当 bug 上报，不要"顺手删掉"。

## 4. 单一职责的判定

不按"听起来像不像一件事"判断，按**变化原因**判断：

> **两个函数/类总是一起改 → 合并；总是不一起改 → 分开。**

这是 `thinking.md` 正交性判据在代码层的用法。触发 `operations/cpp.md` §4 类尺寸红线时，用它决定"抽新类"还是"合并职责"。
