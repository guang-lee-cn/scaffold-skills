# 从这里开始

这套 skills 方法论模板用来引导 AI 把项目**从想法到代码**走完整。它不是什么框架或工具——就是你和 AI 对话时，AI 自动加载的一套工作流指南。

## 5 秒判断：用哪套？

| 你的项目是... | 用这套 | 流程 |
|-------------|--------|------|
| "验证个想法""写个脚本""做个 CLI 工具""搭个 Web 服务" | [Light](light/) | 5 分钟想清楚 → 写代码 → 能跑就行 |
| "C++ 底层组件""嵌入式系统""多进程多子系统""需要完整架构文档" | Heavy（根目录） | 完整 ISO 流程，强制图表和决策记录 |

**不确定？说"开始 ISO，轻量模式"** 试试，不够再切。

## Light 版：三步上手

```
1. 说"开始 ISO，轻量模式"
2. AI 会问你几个问题（做什么、谁用、怎么算做完）→ 回答
3. AI 写代码 → 你确认 → 完
```

如果项目稍微复杂一点（多模块、有外部依赖），AI 会自动多问几个问题、多画一张架构图。不用你手动调。

## Heavy 版：如果你想走完整流程

```
1. 说"开始 ISO"
2. AI 按 Insight → Strategy → Operation 三步执行
   - Insight：挖需求背景
   - Strategy：定目标边界 MVP → 盲点检查
   - Operation：规划落地路径
3. 产出 docs/iso-output.md
   ↓
4. 说"开始设计"
5. AI 按 6 Steps 做架构设计 → 产出接口契约 + 迭代计划
   - 产出 design/xxx.md + contracts/
   ↓
6. 说"实现子系统 A"
7. AI 子 agent 独立编码（可以多个子系统并行）
   ↓
8. 说"集成测试"
9. AI 跑集成 + E2E + 上线检查
```

## 重构已有项目？

**什么算"重构"？** 下面这些场景用重构模式：

- 把旧系统用新架构重写
- 替换已有系统的核心模块（如换数据库、换通信层）
- 已有代码但架构腐化，需要重新设计

**下面这些不算重构，用新建模式：**

- 给健康项目加一个新功能（只是增量开发）
- 从零开始做一个全新的系统
- 写一个独立的工具或脚本

**怎么触发？** 在任何触发词前加"重构"二字：

| 说这个 | 效果 |
|--------|------|
| "重构 + 开始 ISO" | AI 先画现有系统架构图、量化痛点、标记健康资产，再走 Insight 流程 |
| "重构 + 开始设计" | 额外输出迁移策略（绞杀者还是大爆炸）、向后兼容约束、替换优先级 |
| "重构 + 实现子系统" | 额外确认增量替换模式、新旧代码如何物理隔离、旧代码何时删除 |
| "重构 + 集成测试" | 额外规划回归测试、新旧系统对比测试、失败时切回旧系统的方案 |

**和新建模式的核心区别**：

| | 新建 | 重构 |
|---|------|------|
| 起点 | 空白画布 | 现有系统是最大约束 |
| iso.md | 只问"要做什么" | 先评估"现状是什么"，再问"要改成什么样" |
| strategy.md | 只设计目标架构 | 必须设计从旧到新的过渡架构 |
| cpp.md | 从零写新代码 | 新旧代码共存，逐步替换 |
| integration.md | 只测新系统 | 新旧系统对比测试 + 回退切流 |

## 常见问题

**Q: 我能跳过某个阶段吗？**
A: Light 版随时可以。说"跳过设计直接写代码"就行。Heavy 版不建议跳——它的阶段之间有强依赖。

**Q: 怎么加新语言的速查卡？**
A: 在 `light/lang/` 下新建 `rust.md`，参考 `go.md` 的格式写 ~10 行即可。

**Q: Heavy 和 Light 能混用吗？**
A: 不建议。选一套走到底。Heavy 的接口契约格式 Light 没定义，混用会断链。

**Q: 我用自然语言能触发吗？**
A: 能。说"分析需求"→discover，"设计架构"→design，"写代码"→implement，"测试"→deliver。不用记触发词。
