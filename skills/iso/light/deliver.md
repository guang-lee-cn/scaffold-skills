# deliver.md —— 测试与交付

> **定位**：验证代码可用，准备交付。
> **输入**：implement.md 产出的代码 + discover.md 的成功标准。
> **适用**：原型仅确认可运行；小工具做基本验证；业务系统做完整测试。

---

## 0. 执行深度（按规模）

### 原型

```
跑通核心路径 → 确认
```

- 手动跑一遍主流程，确认没崩
- 门禁："核心路径跑通了？(Y/N)"

### 小工具

```
关键场景测试 → 边界用例 → 确认
```

- 覆盖主要使用场景和 2-3 个边界情况
- 不要求自动化测试框架（可以手动 + 脚本）
- 门禁："主要功能和边界都测过了？(Y/N)"

### 业务系统（多模块）

```
集成测试 → E2E → 上线检查 → 确认
```

- 验证模块间接口行为与 design.md 的约定一致
- 覆盖 MVP 核心用户旅程的 E2E 测试
- 上线检查清单（代码合并/测试通过/回滚方案/监控告警）
- 门禁："具备上线条件？(Y/N)"

---

## 1. 测试方法（语言无关）

- 测试验证接口行为，不验证内部实现
- 每个测试用例：给定输入 → 预期输出 → 实际输出
- 失败用例记录：实际 vs 预期 + 根因

---

## 2. 上线检查清单（仅业务系统）

| 检查项 | 状态 |
|--------|------|
| 代码已合并 | ☐ |
| 核心测试通过 | ☐ |
| 回滚方案就绪 | ☐ |
| 关键监控就绪 | ☐ |

---

**文件产出**：
- 原型：不写文件
- 小工具：在 `README.md` 补充使用说明和测试方法
- 业务系统：`docs/test-report.md` + 上线清单
