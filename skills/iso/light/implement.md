# implement.md —— 通用实现

> **定位**：语言无关的编码实现。根据项目技术栈自动加载 `lang/` 下对应速查卡。
> **输入**：discover.md 的范围摘要 + design.md 的架构草图（如有）。
> **适用**：原型 / 小工具 / 业务系统，执行深度按规模递增。

---

## 0. 技术栈确认

AI 确认技术栈后，加载对应的语言速查卡（`lang/cpp.md`、`lang/go.md`、`lang/python.md` 等）。如果 `lang/` 下没有对应文件，按通用最佳实践执行。

---

## 1. 执行深度（按规模）

### 原型

```
写代码 → 能跑 → 确认
```

- 单文件或少量文件，不建复杂目录结构
- 不强制写测试
- 代码注释标注 TODO 和已知限制即可
- 确认："代码能跑通核心路径了吗？(Y/N)"

### 小工具

```
目录骨架 → 核心模块 → 关键测试 → 确认
```

- 基本目录结构 + 构建配置
- 核心路径必须有测试（不需要全覆盖）
- 确认："功能可用、关键路径有测试？(Y/N)"

### 业务系统

```
框架搭建 → 子系统逐个实现 → 质量检查 → 确认
```

- 项目骨架 + 公共基础 + 测试框架
- 按 design.md 的模块顺序逐个实现
- 每个模块：接口定义 → 测试 → 实现 → 自检
- 质量：静态检查零警告 + 单元测试通过 + 无内存泄漏

---

## 2. 编码原则（适用所有规模）

1. **可运行 > 完美**：先让代码跑起来，再优化
2. **命名自解释**：不需要注释解释"这段代码在干什么"
3. **错误不忽略**：所有 error 要么处理，要么显式向上抛
4. **边界完整**：空输入、极端值、超时都要处理
5. **一次做好一件事**：一个函数只做一件事，超过 40 行考虑拆分

---

## 3. 多模块并行（仅业务系统）

如果 design.md 定义了多个无依赖的模块，AI 可以建议：

> "模块 A、B、C 之间无依赖，可以并行实现。要我现在拉起并行 agent 吗？"

并行时每个子 agent 只拿到：本模块的接口约定 + lang/ 速查卡 + 本文 §2 编码原则。不给全局架构和需求背景。

---

## 4. 质量门禁（语言无关）

每完成一个模块（或交付前，按 §1 的规模深度），按**项目声明的能力**跑门禁——C1 格式一致性 / C2 静态缺陷扫描 / C3 接口与类型检查 / C4 资源与内存验证 / C5 复杂度阈值 / C6 测试存在性与执行。

- **工具由项目决策，ISO 不绑定**：本项目用哪些工具、命令、阈值、锁定版本，记录在项目侧 `docs/quality-gates.md`
- **判定协议**（四态判定、降级记账、强度分级）见 [../references/quality-gates.md](../references/quality-gates.md)
- **禁止静默通过**：能力未声明、或工具已声明但环境未安装时，必须显式报出该状态，不得当作通过

---

**门禁**：按规模确认（见 §1 各规模确认语），并追加：

> *"本项目声明的质量能力已全部通过，或已按降级协议记账？(Y/N)"*

**文件产出**：
- 原型：源代码
- 小工具：源代码 + `README.md`
- 业务系统：源代码 + `docs/design/sub-{name}.md`（每个模块）
