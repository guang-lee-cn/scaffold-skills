# issues.md · 问题管理（四分类 + L1/L2 + 复盘 + 价值流）

## 1. 问题四分类（G 定案）

主类必填、次类可选，格式 `[<主类>][<次类>] I<编号> · 标题`

| 类 | 标签 | 定义 | 处置/归档去向 |
|---|---|---|---|
| 环境/工具（项目无关）| E | OS/开发工具报错（wsl、UNC、PowerShell、资源占用…）；影响进展不涉正确性 | 命令基线/环境坑清单；不进 ADR |
| 核心（项目直接相关）| C | 领域/架构/实现问题；决定交付物正确性 | ADR/契约/设计文档；影响后续单元 |
| 工具链/测试约定 | K | gtest/ctest/编译链；与代码强相关 | 测试规范 / CI 子方案 |
| 流程/协作 | P | 文档落盘/验收/交接遗漏 | SOP / record 修订 |

## 2. 问题分级 L1/L2

- **所有问题编号留痕**（I<编号> 全局顺延，V<编号> 价值流独立顺延）
- L2 = 独立复盘文档（九段式）；L1 = 复盘文档末尾紧凑记录（**含解决过程**，非一句话）
- **L1→L2 判定（性质导向，不卡时间）**：① 死锁/内存泄漏/coredump/数据损坏/行为错误 ② 需代码/设计变更 ③ 有架构/方法论教训 ④ 影响验收排期

## 3. 复盘模板（L2，九段式：根因分层 + 改进措施闭环）

1. **概要**：一句话 + 分类标签 + 影响 + 关联提交
2. **环境信息**：OS/编译器/依赖版本/工具链（精确版本）
3. **问题现象**：真实日志/输出（贴原文）+ 触发用例清单
4. **期望**：期望行为 + 为什么期望（对齐目标，勿写"当然应该通过"）
5. **故障复现方法**：触发用例名 + 复现命令（可复跑）
6. **诊断时间线**：动作+命令+每步输出+结论；**决策痕迹**（谁/何时/拍板什么——SRE 最常缺失的一层）
6.5 **多视角交叉验证（Oracle）**：单一假设链 2 轮验证失败后——换 ≥3 个独立视角（架构视角/运行时视角/工具视角）各自独立判读根因 → 交叉确认（防单一路径盲区）。Oracle 源自测试领域"独立判官"概念：工具实证 = 确定性 Oracle；多视角独立判读 = Oracle Triple——与 ai-code-review 校验 AI 同构
7. **根因分析**：
   7.1 **技术根因**（三分类，标主导/次要）
     - 方案：设计/选型/契约语义层缺陷
     - 代码：实现层缺陷（位置/关键字）
     - 其它：依赖/上游/环境/工具/数据
     - 5Why 链并入本节作深度支撑（关键代码关键字 + 关键节点）
   7.2 **管理根因**（流程环节守护：为什么没被早期拦截）
     - 通用环节：设计评审 / 代码评审 / 单测设计 / CI 门禁 / 静态动态检查 / 发布检查单 / 监控可观测 / 文档交接
     - 项目特化环节：由项目 record skill 增补（如契约评审）
     - 逐项判定：**已守护**（拦住了同类）/ **生效但漏过**（环节存在未覆盖此场景）/ **缺位**（环节不存在）
     - 仅"缺位"与"生效但漏过"记管理根因；"已守护"不记
8. **改进措施**（两部分闭环，每条带验证+关闭条件）
   8.1 **技术改进**：修什么（代码/方案/配置）+ 验证方式 + 关闭条件
   8.2 **管理改进**：补什么（流程/门禁/检查单）+ 生效方式
   （格式：`Action | Owner | 验证方式 | 关闭条件 | 优先级`）
9. **遗留与后续**：未决项 / 追踪 / 引用 V 编号

## 4. 价值流（非故障可复用经验）

- 触发词：价值流/技巧/经验/亮点/方法论
- 编号 V<编号> 独立顺延；模板见 docs-templates.md §3
- 源自问题的价值由复盘 §8 引用 V 编号，单独成文

## 5. 归档位置

- 复盘：项目设计目录（本地仓库，白名单外不进远端）
- 问题台账：隐私区（不进 git），日报只引用编号
