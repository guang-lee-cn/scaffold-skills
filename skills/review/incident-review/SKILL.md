# 事故复盘纪律（incident-review）

> 版本 1.0 | 2026-08-20 | 三源融合，提炼并实战校验于 dts-framework OOM 事故复盘
>
> 核心命题：**事故是已经付过学费的教材；复盘的产出不是报告，是"不再重演"。**

## 0. 触发判定：什么才算"事故复盘"

满足任一条即启动本流程，一条不占则直接修完为止（普通 bug 不需要仪式）：

| 判据 | 含义 |
|---|---|
| **重演** | 同一故障发生 ≥2 次（学费交了第二次还没换来教训） |
| **弯路** | 排查显著走偏（误诊、换错方向、依赖了错误前提） |
| **超损** | 影响超出预期（崩机、断连、资损、波及无辜系统） |

口诀：**重演、弯路、超损——占一条就复盘。**

## 1. 全周期总览：三本书各管一段

```
准备期 ──→ 响应期 ──→ 复盘期 ──→ 转化期
(演练/护栏)  (Google)    (陈中)      (邱昭良)
```

| 来源 | 管辖 | 一句话职责 |
|---|---|---|
| Google《Anatomy of an Incident》 | 事前 + 事中 | 保证**事故别重演两次**（护栏、缓解优先、证据留存、无责） |
| 陈中《复盘：对过去的事情做思维演练》 | 事后分析 | 保证**问到自己哑口无言**（四步流程 + 审视前提） |
| 邱昭良《复盘+：把经验转化为能力》 | 事后转化 | 保证**下一次不需要人想得起来**（双环学习 + 经验资产化） |

典型失败模式：只用第一本 → 复盘流于格式；只用后两本 → 事故在排查期间又炸了两次（响应纪律缺位）。

## 2. Phase 1 响应期纪律（事中，出处：Google）

**这一段发生在复盘开始之前，但决定复盘的质量上限。**

1. **缓解优先于根因（mitigation first）**：先隔离触发源/回滚/降级，恢复稳定后再从容查因。
   自检判据：*"再触发一次，系统还安全吗？"* 答案是否 → 先做隔离，不许直接开查。
2. **证据立即留存**：崩溃/断连时刻当场固定 `journalctl -k`、`dmesg`、应用日志**导出到磁盘**。
   崩溃会带走页缓存里未落盘的一切；事后法证远贵于当场一条重定向。
3. **时间线边处理边记**：每个动作打时间戳。事后凭记忆拼时间线 = 给误诊留门。
4. **跨 boot 查硬故障史**：崩溃/断连类排查的第一动作固定为
   `journalctl -k --since <事发日> | grep -iE 'oom|panic|oops|lockup'`——
   **先排除硬故障（内核层），再分支推理（应用层/网络层理论）**。
5. **无责（blameless）**：复盘对事不对人。一旦变成追责会，真实过程就再也没人愿意完整给出。

## 3. Phase 2 复盘期（事后分析，出处：陈中）

### 3.1 四步流程

```
回顾目标 → 评估结果 → 分析原因 → 总结规律
```

### 3.2 三问（顺序不可换）

1. **现在情况如何？**（事实层）
2. **当初是怎么决定的？**（决策层——还原决策时的信息与依据，不是事后诸葛亮）
3. **让我们审视一下思考的前提。**（认知层）★ 复盘真正的价值所在，多数复盘死在没问这一句

### 3.3 事实完备性门禁（5W1H）——进入原因分析前的必过闸

| 要素 | 技术事故的具体化要求 | 常见缺位 |
|---|---|---|
| What | 现象的精确度量（多少 GB、几次、什么速率） | "内存耗尽"这种泛描述 |
| When | 完整时间线，**含跨环境/跨重启的全部发生点** | 只看本次，漏掉历史同款 |
| Where | **精确到层**：内核 / VM / 进程 / 网络 / 框架接口语义 | 定错层 = 排查错层 |
| Who | **精确到进程/模块/代码路径**，不止"哪个人" | "哪个组件"级别的模糊指认 |
| Why | 此时只许填**表层因果** | 提前锚定根因，后面全在自证 |
| How | 实际处置动作（含走错的那几步） | 只记对的，弯路消失 |

**门禁规则：六格不全，不得进入原因分析。**

⚠️ 5W1H 的经典误用：把填完六格当成复盘完成——那得到的是一份结构良好的**事故报告**（描述完备），不是**学习**（没有因果深度、没有前提审视、没有转化动作）。它是门禁，不是本体。

### 3.4 前提陷阱清单（第三问的工程化弹药）

| # | 陷阱 | 真相 |
|---|---|---|
| ① | "验证过 = 没问题" | 验证只是"**某环境 × 某路径**"组合的通过；任一变化即失效 |
| ② | "文档记录 = 事实" | 记录者只看到了自己所在环境的分支；文档会滞后于现实 |
| ③ | "时间相关 = 因果" | 环境里有真实慢性噪声时尤其危险——真病掩护死因 |
| ④ | "参考实现 = 语义相同" | 抄返回值必须连它的**消费方式**一起抄（抄一半是移植 bug 之源） |
| ⑤ | "没跑起来 = 没执行" | 命令可能已在服务端执行，只是结果随崩溃丢失 |

### 3.5 因果深挖（5 Why）

对 5W1H 里那个表层 Why 连问五个"为什么"，直到碰到**可修改的机制**（而不是可指责的人）。
停止判据：下一层答案是"人会小心" → 没到底；答案是"给脚本加 ulimit" → 到底了。

## 4. Phase 3 转化期（出处：邱昭良）

### 4.1 双环学习

- **第一环：修正行为**（这次改了什么——加钳制、改阈值）
- **第二环：修正产生行为的认知前提**（下次换场景还会犯的那条心智模式）

例：第一环 = "收缓冲要钳制到配置值"；第二环 = "把'验证过'这个词降级——验证过的永远只是环境×路径的组合"。**只做第一环，同类问题换着环境再来。**

### 4.2 经验资产化三分法（行动项必须指认载体）

| 资产类型 | 形态 | 判据 |
|---|---|---|
| **工具护栏** | ulimit/超时/断言进脚本、CI 门禁 | 不需要任何人记住 |
| **SOP** | 排查第一步固定动作、操作手册条目 | 写进流程，依赖流程而非记性 |
| **契约** | 代码注释、接口文档、设计文档条目 | 跟随代码被审查 |

**验收规则：说不出某条教训"活在哪个载体里"，视为未完成。**

## 5. 工具选型表（防误用）

| 层 | 工具 | 防的失败模式 | 出处 |
|---|---|---|---|
| 时序还原 | 时间线 | 凭记忆拼事件顺序 | 通用 |
| 事实完备 | 5W1H（门禁） | Who/Where 定不到位、错层 | 质量管理经典 |
| 因果深度 | 5 Why | 停在表层原因收手 | 丰田 |
| 原因发散 | 鱼骨图 | 单因假设、漏系统性原因 | 质量管理经典 |
| 认知层 | 审视前提（第三问） | 只修行为不修前提 | 陈中 |
| 心智修正 | 双环学习 | 前提修了但不固化 | 邱昭良 |
| 全周期 | 生命周期管理 | 事故在复盘完成前重演 | Google SRE |

## 6. 复盘文档模板（五段）

```markdown
# <事故名> 复盘（<日期>）
## 1. 事实（5W1H 六格 + 完整时间线，含跨环境发生点）
## 2. 根因链（从现象到可修改机制的完整因果链，标注证据等级：铁证/推断/继承）
## 3. 为什么没拦住（测试、护栏、流程各缺了哪道防线）
## 4. 为什么走了弯路（诚实检讨：前提陷阱命中了哪几条）
## 5. 改进措施（双环两行 + 每项注明资产载体：工具/SOP/契约）
```

证据分级借用 ros2-amr-debug 的三级制：**铁证**（原始数据可复现）/ **推断**（机制合理未做区分实验）/ **继承**（他人结论），禁止把推断说成确定。
