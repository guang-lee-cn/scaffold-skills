# 关键依赖工具安装（不可跳过）

## 判定

1. 当前任务的最有效手段是否依赖某工具？是 → 进入本规则（如 valgrind 内存泄漏检测、uncrustify 格式门禁、cppcheck 静态扫描、gcov/lcov 覆盖率，无可替代手段）。
2. 该工具未安装/不可用/版本不符，且安装需要权限（sudo / 管理员 / 仓库外安装）？

**两条都满足 → 该步骤为阻塞态，禁止降级。**

## 禁止行为

- 禁止跳过该门禁/验证步骤（"先不跑，后续补"不成立——最有效手段缺失即证据缺失）
- 禁止换弱工具或近似手段顶替（格式检查替代 uncrustify、内存自检替代 valgrind 等）
- 禁止静默继续并宣称完成
- 禁止擅自提权安装或改用户环境（安装权限在协作者）

## 动作

1. 明确标注该步骤为**阻塞态**：`待「<工具名>」安装后继续`，写入工作记录。
2. 给协作者**可直接执行的精确安装命令**：包管理器命令（apt/brew/dnf 等）+ 版本要求 + 安装后验证命令（`<tool> --version` 或指定验证）。
3. 安装完成后，先运行验证命令回验（版本/可执行/关键参数符合要求），**验证通过后再继续原工作流**，并在工作记录回填安装结果。
4. 若多个环境（本机/WSL/CI）都依赖该工具，命令按环境分别给出，各自验证。

## 记录

- 安装请求（工具、命令、原因）与安装结果（版本、验证输出）记入工作记录/日报，不得只留在对话中。
